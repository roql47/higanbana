# 우물 물증·게다 묘역 모델 및 텍스처 마감

## 반영한 결과

- 환자복은 Blender로 제작한 GLB로 교체했다. 목·소매·밑단이 열려 있고 주름, 천 두께, 재봉 바인딩, 앞섶/단추, 등쪽 끈, 철사 옷걸이와 이름표가 있다. 직물·십자 무늬·젖은 밑단의 바탕/거칠기 맵을 포함한다. 이름표는 한국어/일본어 캔버스를 패치 UV에 입힌다.
- 최초 내보내기에서 이름표의 UV가 최적화로 제거되는 문제를 발견했다. 단색 텍스처도 제거되므로 재봉 테두리 텍스처로 UV를 보존하고, 최종 배포 GLB의 UV/재질 연결을 테스트한다.
- 소매와 목마는 기존 텍스처 GLB를 유지한다. 선반에 모따기·몰딩·지지대·실제 크기 UV/노멀맵을 적용했고 목마를 옆모습으로 돌려 몸통·바퀴·고삐가 보이게 했다. 안전 벽감과 조사 판정은 유지한다.
- 숨은 묘역의 석등·묘석·이끼 돌을 실제 텍스처 모델로 교체했다. 돌 담장의 받침/갓돌/줄눈, 장식 기둥, 층진 공물 받침대, 목재 문짝·문고리·돌 문틀을 추가했다. 흙/자갈 바닥과 직물 받침 천도 마감했다.
- 남겨진 게다와 미끼도 실제 공물 GLB를 공유하며 어른용 크기와 수선 표식을 보존한다. 진짜 공물은 계속 Rules가 소유한다. 기존 바닥/벽 충돌, 조사점, 착지/귀환점과 퍼즐 상태는 유지한다.

원본: `assets/authored/hanging-gown/hanging-gown.blend`. 생성: `scripts/blender/build-hanging-gown.py`. 배포: `public/models/props/haru-hanging-gown.glb` (512px WebP + meshopt, 약 0.19MiB). 기존 묘지 모델은 새 외부 다운로드 없이 재사용했다.

## 리소스

묘역은 StreamedDetail로 접근 시 선로딩하고 멀어지면 해제한다. 순간이동/이어하기도 모델 준비를 기다리며 실패하면 대체 외형과 충돌을 보존한다. 석등/묘석/돌은 인스턴싱하고 구조물은 재질별 병합한다. 새 그림자 광원은 없다. 검수 시 아트 루트는 메시 29개, 반복 인스턴스 35개, 반복을 포함한 삼각형 105,296개였다. 게임 전체 드로우콜/GPU 메모리 측정값은 아니다.

공유 월드 타일은 해제하지 않고 로컬 텍스처 복사본과 소유 모델만 해제한다. 미끼 그룹에 부착한 상세 모델도 함께 해제하고 재진입 시 한 벌만 생성한다.

## 이전 앱과 새 지도 차이

조사 전 원본 앱은 `main-B_Erz1jx.js`, 앞선 수정 패키지는 `main-DQhvs4In.js`였다. **둘 다 같은 GraveyardHollow와 같은 착지점 (-40, -17.88, 22.5)을 사용한다.** 구 앱은 외곽 벽 5.4m, 칸막이 2.4m, 단색 바닥/기둥이었다. 수정판은 외곽 2.6m, 칸막이 1.7m와 변경된 바닥/조명으로 외형이 달랐다. Computer Use 전용 맵이 따로 있는 것은 아니다.

사용자가 보았다는 기존 집 내부 현상 자체는 재현하지 못했으므로 그 화면의 원인을 버전 차이 또는 집 이동 버그로 단정하지 않는다. 이번 콘텐츠는 `main-C1HEL4V8.js`다. 종료 상태를 확인한 원본 `src-tauri/target/release/bundle/macos/Higanbana.app`도 최신 콘텐츠로 갱신하고 다시 서명했다. 사용자 저장 프로필은 변경하지 않았다.

## 검증

- 타입 검사 및 전체 테스트 **104개** 통과. 새 테스트는 배포 GLB 이름표 UV 보존, 묘역 해제/재진입 시 공유 타일 보존 및 부착 모델 정리다.
- 브라우저 실제 보행/E 조작으로 진입 → 발자국 → 조기 귀환 → 재진입/내부 저장 재개 → 남겨진 짝 → 가짜 게다 → 정답/획득 → 가짜 문 → 운반 중 저장 재개 → 붉은 매듭 귀환/작별까지 통과했다.
- 게임 1인칭에서 환자복/이름표/소매/목마와 묘역 석등/받침대/게다를 확인했다. 목마 몸통과 바퀴가 벽에 가리지 않는다.
- 별도 식별자 `com.higanbana.optimizationqa`의 macOS 앱에서 동일한 프로덕션 콘텐츠로 묘역과 환자복 앞 체크포인트를 실행했다. WKWebView에서 석등·묘석·돌벽과 환자복·이름표를 확인했다. QA 체크포인트 버튼은 이 앱에만 넣으며 배포 ZIP에는 없다. 강제 새로고침 중 이전 문서 오디오 디코딩의 `Document is not fully active` 경고가 있었으나 새 장면은 정상 로딩됐다.
- 네이티브에서 전체 퍼즐을 재주행한 것은 아니다. 전체 퍼즐 보행은 브라우저 검증이며 Windows 실기기 실행은 미수행이다.
